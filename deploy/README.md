# 公网联机部署

同一套服务端可以供网页版和微信小程序共同使用。玩家只要能访问这个公网服务，就可以通过房间号加入，不需要同一个 Wi-Fi，也不需要把手机端口暴露到公网。

## 1. 准备服务端

需要一台公网服务器或支持长期运行 Node.js 的托管服务，以及一个绑定到服务的 HTTPS 域名。当前项目需要 Node.js 18 或更新版本。

在服务器放置整个项目并运行：

```sh
node web/server.js
```

也可以在项目根目录构建并运行 Docker 容器：

```sh
docker build -t plane-duel .
docker run -d --name plane-duel --restart unless-stopped -p 127.0.0.1:3000:3000 plane-duel
```

若使用云平台的容器托管，配置容器端口为 3000，允许平台通过 HTTPS 转发到该端口。服务支持平台通过 PORT 环境变量指定端口。

房间目前保存在内存，请先运行**一个实例**，不要启用多实例负载均衡。服务重启会清空房间；房间连续两小时无人访问会过期。

## 2. 绑定 HTTPS

以 Caddy 为例，在已安装 Caddy 的服务器上，将域名 DNS 指向该服务器，允许公网访问 80 和 443。Caddy 配置示例：

```caddyfile
game.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

将 `game.example.com` 换成真实域名，加载配置后 Caddy 会申请和维护证书。也可使用本目录的 Caddyfile，并为 Caddy 进程提供 GAME_DOMAIN 环境变量。使用其他代理时保留原始 Host；代理改写 Host 的平台可为 Node.js 设置 `PUBLIC_ORIGIN=https://真实游戏域名`。

在不同网络的两台设备打开 `https://真实游戏域名`，一人创建房间、另一人输入房间号加入，即可验证网页版远程联机。浏览器从同一域名加载网页与 API，不需另填服务端地址。

## 3. 接入微信小程序

1. 将 `miniprogram/config.js` 中的 `serverUrl` 填为 `https://真实游戏域名`，不要带末尾斜杠。所有发布版本使用同一个地址。
2. 将 `miniprogram/project.config.json` 中的占位 `touristappid` 替换为自己的正式小程序 AppID。
3. 在微信公众平台的小程序后台，将该 HTTPS 域名加入 **开发管理 → 开发设置 → 服务器域名 → request 合法域名**。域名、证书及备案需符合微信平台当前要求。
4. 在微信开发者工具中编译。项目当前关闭了开发工具的域名校验，只能方便本地调试；正式真机联网仍需正确的 HTTPS 证书与合法域名配置，建议开启校验后测试。
5. 上传体验版，用两台手机（例如一台 Wi-Fi、一台移动数据）分别创建、加入同一个房间。也可以一端小程序、一端网页，二者共用房间与规则。

小程序使用 `wx.request` 同步状态，前台约每 800 毫秒查询一次，切到后台暂停，回到前台恢复。房间凭证保存在本机，重新打开可恢复；红旗是个人笔记，重新打开后不保留。

本仓库提供了联机代码、Dockerfile 和代理配置示例；没有自动创建云服务器、注册域名、申请小程序 AppID 或发布小程序。完成以上实际配置后，才可进行公网与微信真机联机。
